# Changelog

All notable changes to aibars are documented here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- A global keyboard shortcut that opens the panel, recorded in Settings → General → Keyboard. Nothing is bound until you record one. It goes over Carbon's `RegisterEventHotKey` rather than `NSEvent.addGlobalMonitorForEvents` or a `CGEvent` tap: those two need Accessibility permission and cannot take the keystroke away from the app in front, so the combination would also type into whatever was frontmost. Carbon needs no permission and no entitlement, and the WindowServer withholds the combination from everyone else while aibars holds it. Its binding lives in its own `aibars.hotkey.*` namespace, not with the appearance settings, whose key domain is emptied once per generation of the look. The recorder refuses the combinations macOS itself holds, read live from `com.apple.symbolichotkeys`; nothing on macOS can say who holds the rest, so the footer says that in words rather than offering a test button that could only report silence.
- Type-to-filter in the panel. The first printable character turns the header's summary into a filter line — no text field, no bezel, no focus ring. Matching runs over a row's name, its initials, a short alias list, its account label and its plan, all of them strings the row actually prints, in bands rather than a summed score, with ties keeping the panel's own order. A match your settings have hidden is named and pointed at the pane it went to rather than silently resurrected.
- Keyboard navigation of the whole panel: ↑ ↓ Home End to move a selection that clamps rather than wraps, ⌘1–⌘9 to select the nth row, Return to open or sign in, Esc to clear and then close, ⌘F to begin filtering with nothing typed. Every other ⌘ chord is passed straight through, because key equivalents are dispatched after local event monitors and an app with no Dock icon that swallowed ⌘Q would be unquittable.
- Six drawings for the menu bar strip — mark + figure, figures only, marks only, micro bars, mark + meter, and closest-to-its-cap — each a type of its own under `Sources/Views/StripStyles/`, chosen from a grid of chips in Appearance → Menu bar that carry the status item's real view rather than a picture of it. A style answers a cell width, a service ceiling, a sentence shape and a drawing, and its width signature has no parameter that could carry a reading, so a style cannot size itself from the string in hand.
- A 24-hour sparkline under each connected row's meter, off by default. One neutral trace of the headline window's hourly peaks: no usage colour, because the meter beside it is the reading and this is context. Gaps are cut rather than bridged, a window rolling over cuts it at the same 30-point drop the history chart splits on, and the slot is reserved from the setting rather than from whether there is anything in it, so a row cannot grow when its own history arrives.
- A 90-day heatmap in the History pane, between the chart and the table. One neutral luminance ramp whose four filled steps are even quarters of the range below your own warning line, with a hue only at or over that line; a day that crossed its cap loses its corners rather than taking a sixth colour. Fourteen columns always, pushed right so today's week is last, and a fixed box whatever landed in it. One focus target rather than ninety, with the arrows walking a pinned day by ±1 and ±7 through the cells rather than through the calendar, which is what keeps them right across the spring-forward Sunday.
- A redline on the usage meter: a one-point notch of the panel's own ground standing at the warning threshold and drawn over the fill, so the fill can visibly run past it. It is the only near-cap channel that is pure position, and unlike the pace riser it replaces it measures the same quantity the fill already does, so there is nothing for a reader to learn.
- `ZZPanelSnapshot`, which renders the whole panel — header, sections, every row state — to PNG in both appearances at 300, 356 and 520pt, and `PanelWidthContractTests`, which draws the panel into a canvas wider than itself and scans the margins for ink. `fittingSize` cannot answer the overflow question from either end: asked of the panel it returns the panel's own width, asked of a bare row it over-reports.
- `AppDefaults`, which hands the app `UserDefaults.standard` and hands a test run a scratch domain, plus `TestIsolation` for the fixtures that need a store of their own.
- Four more providers: Google Gemini, Grok, Perplexity and DeepSeek. Gemini, Grok and Perplexity read a session cookie; DeepSeek uses an API key from its platform console. Every endpoint here is undocumented except DeepSeek's, so each provider notes in-file how much of its response shape is confirmed.
- OpenRouter and Mistral. OpenRouter uses a pasted inference key (`sk-or-v1-…`) from openrouter.ai/settings/keys against its documented credits and key routes; Mistral reads the `ory_session_<slug>` cookie from admin.mistral.ai, since its official usage API is Enterprise-only and in preview.
- Chromium cookie decryption, which is what makes signing in through Chrome, Edge, Brave, Arc or Opera possible at all. The Safe Storage key comes from the login keychain, so the first read prompts for access.
- Per-row refresh and a link out to each service's own usage page, revealed on hover.
- Commit conventions in `CONTRIBUTING.md` plus a `.gitmessage` template.
- One-click sign-in: aibars opens each provider's own login page in your default browser and picks the session up out of that browser as soon as it appears, replacing the DevTools copy-paste flow. The connect window keeps a "paste a token instead" fallback for browsers aibars can't read.
- Real provider logos, drawn from single-path SVG data by a new SVG path parser (`Sources/Brand/`). Near-black marks flip to light on dark backgrounds. A bundled `logo-<providerID>` image overrides the built-in mark.
- Menu bar meter: one bar per service, tallest first, tinted only on the bars that are actually near their cap.
- `Sign in` button directly on a disconnected provider's row in the dropdown.
- Appearance pane in Settings: presets (Comfortable, Compact, Minimal, Dashboard, Monochrome) plus per-option control over density, colour, ordering and the menu bar mark, with a live side-by-side preview of the panel and of the mark.

### Changed
- **The palette is rebuilt neutral, and there are now exactly two hues in the whole application — amber and red — both meaning alarm and nothing else.** The panel was running three colour systems in 356 points: fifteen brand marks at full saturation, a usage ramp with its own amber and red, and a semantic green/amber/red beside them. The raw brand hexes out-chromaed every colour that meant something, so an alert could not announce itself over the row's own logo. Grounds drop to near-black `#0C0D11` and near-white `#F6F7FA`; text, marks, captions, the meter's track and resting fill and the heatmap's steps all come off one greyscale.
- Brand marks carry the brand's own hue when their row is connected and reporting, and the muted grey the row's name and caption take in every other state — so colour on a row means what colour means everywhere else in the panel: this one is live. It is hue only: the live band holds the mark grey's exact lightness and caps chroma below the alarm amber's, so no contrast ratio in the app moves when it is switched off. Seven brands with no hue fall through to the mark grey, which is the same rule at zero chroma rather than an exception to it.
- Every contrast figure in the design system was recomputed against the new ground rather than carried over, and the measurement plane moved to the worst case the app can actually draw — a pressed card over a white wallpaper. The scrim went to 0.94 dark / 0.96 light, which makes the panel markedly less translucent; the alternative left the empty half of every bar darker than the ground behind it under a bright desktop.
- The meter's track is capped at 160pt and leading-aligned, so it no longer grows with the panel. At the shipped width it was 304pt of a 356pt window — 85% of it, aspect 61:1 — and 468pt at the top of the width slider. At that length a 0% row was a full-bleed rule between a title and its own caption at ten times the thickness of the panel's real divider, one amber bar was over 90% of all the colour in the window, and the track resolved a third of a percent per point against a figure printed to the nearest whole one.
- The minimum-fill floor is now the smaller of two bar thicknesses and 4% of the track. On a 160pt track the old thickness-only floor would have drawn every reading under 6% as 6% while the figure two columns away printed the truth.
- The usage ramp's resting stop is its own grey rather than the muted text ink, which is what gives the ramp's first boundary a greyscale step: 1.06:1 and 1.9 L\* between resting and caution becomes 1.60:1 and 13.8 L\*, and the ramp is monotone in lightness in both appearances for the first time. Under the per-bar menu bar colour the strip uses its own neutral below caution instead, because that ink is solved against the meter's track and the strip is a figure on the desktop's ground.
- A row's height is a function of its settings and whether the account is authenticated, and of nothing else — never of the fetch result, never of a measured string. `MenuBarExtra` sizes its window to its content, so anything content-dependent resizes the panel under the pointer.
- The reserved-but-undrawn meter slot on a quotaless row is placed after the caption rather than before it. Same children, same spacing, identical height; what moves is where the air falls. Measured on the shipped render, the largest gap on four of nine rows was *inside* the row — 18pt within against 26pt between, and under Minimal it was every row at 1.20× — which is a wall of text. It is now 10 against 34.
- The group break between connected and not-connected rows widened from 8 to 16pt. At 8 it measured a point *tighter* than the seam between two ordinary rows.
- The panel header stands on the rows' own axes. It used to work its wordmark's position out from a 14pt mark and a fixed gap while a row worked its name out from the logo and the leading column: two sums for one column, agreeing at no logo size at all. The wordmark and every service name now begin on the same point, and the header's glyph ink lands on the same right rail the figures and chips do.
- The countdown outranks a secondary chip at or above caution, so the flagship row reads `5h session · resets in 1h 19m` + `Weekly 61%` + `+1` rather than dropping the reset to fit a third chip. Width only — the caption is one line box whatever is on it.
- Chip readings take the mark ink rather than the body ink. The Claude row's headline `92%` sits at one lightness under two chips that were 2.37:1 brighter than it: the two least important numbers on the row louder than the most important one.
- A failed row's name takes the muted ink, matching its mark. Two docs stated opposite rules for one state and the row drew both, so a row that had *failed* read healthier than one merely loading.
- The chip's anti-jitter floor is spent before its label rather than between the label and its own number, closing a 26pt hole inside a chip that had 8pt between it and the next one.
- The app mark is cut on a whole-point grid. It was soft in the menu bar for four reasons at once: an odd box centred in an even slot, ink 0.9 of its own plot, a corner radius that ate a 3pt stem, and a descent whose four steps were 3, 3, 2. `AppMarkGeometry` answers all four as integer arithmetic with no view in it, and at boxes 12, 14 and 22 there is not one partially lit pixel above the axis at 1× or 2×.
- The two outline brand marks are clamped by silhouette rather than by coverage. Coverage normalisation over-inflates a shape that is mostly hole: Grok and OpenCode were drawing 16.0×15.5 and 9.0×10.0 against 12×12 for everything else, a 2.76× spread in area. Longest-side spread is now 1.11×.
- History reads answer without the main actor. Eleven rows each asking for their own samples inside one `body` pass was eleven synchronous SQLite queries on the drawing thread, some of them queued behind the insert transaction of the sweep that opened the panel. `peaks`, `days`, `allSeries` and `exportCSV` are `nonisolated async` now, bucketing on the database queue.
- The History pane loads through one `.task(id:)` keyed on the store's revision, the range and the chosen series, so a body drawn mid-load shows one picture that is a moment stale rather than three half-updated ones.
- The extra-windows setting is called "One line per window" rather than "Full bars". It has drawn no bars for two passes.
- The panel's list cap is measured off the screen under the pointer rather than off `NSScreen.main`. An app with no Dock icon and no window of its own does not reliably hold the key window, while its status item exists on every display's bar.
- Icon buttons take a required accessibility name rather than a defaulted one. A default closes the six buttons that exist and lets the seventh be added nameless, which is how all six came to announce their SF Symbol.
- `AppearanceSettings.Key` is internal rather than private, so a test can assert that no appearance key collides with the three hotkey keys.
- CI gains `workflow_dispatch`, a step that maps the generated project's `objectVersion` to the Xcode major it needs and fails with a sentence naming both, and a longer timeout. `brew install xcodegen` takes whatever Homebrew ships that day, so the project format was being chosen by a package index; the day it writes a format the runner cannot read, the job now says so instead of "The project is damaged and cannot be opened".
- Redesigned the dropdown: logo tiles, plan pills, gradient usage bars, compact `3h 12m` countdowns, and per-service secondary chips.
- Signing out now clears aibars' stored credential and remembers the choice, so the next launch sweep does not re-adopt the browser session. The browser's own cookies are left untouched.
- Copilot reports its seat as a status rather than a `1/1` quota, so an active seat no longer reads as 100% used.

### Removed
- The pace riser, the slit cut through the fill, and the two-tone elapsed track. The bar drew two quantities where the rest of the category draws one, and nobody could read it: an instrument nobody arrives already knowing has to be documented before it can be used, and a menu bar panel is not a thing people read documentation for. Pace keeps its sentence under the meter, so what went was a drawing and not a reading.
- The coloured spine down a row's leading edge, and the amber padlock that briefly stood in the same place. One vertical mark meaning near-cap *or* needs-you *or* failed-outright, with no way to recover which from looking at it. Near-cap keeps the square cap, the heavier figure, a visibly full bar and the redline without it, and "this one needs you" is now the word `Sign in` in the row's own figure rail.
- `Ink.arc` and `Ink.ok`, with tombstones recording what they carried. The app's indigo is `Ink.body` now, and the one green dot is the body ink too: a connected service that is not answering was never green, and the dot's job is proof of connection rather than approval.
- `ZZStatesSnapshot`, which wrote two PNGs to `/tmp` on every `xcodebuild test`, gated on nothing, while its own comment said it had been deleted. It drew six bare rows on a flat ground at a hard-coded width, which is the one arrangement that cannot show a row escaping the panel's frame. `ZZPanelSnapshot` supersedes it, and a full run now writes no file matching `/tmp/aibars_*`.
- `GlobalHotkey.didFailToOpen`. It duplicated the published state, nothing read it, and it was assigned on the *success* path, so every press republished the object and redrew the Shortcuts pane.
- `SettingsWindowController.close()`, which was public, had no callers, and would have been wrong if it had any: `isReleasedWhenClosed` is false precisely so the red button leaves the window standing with its size, position and pane for the next press of the gear.

### Fixed
- **A panel whose every row had slid sideways and lost its brand mark off one edge.** `RowGeometry.chipWidth` was modelling a secondary chip that had stopped being drawn two passes earlier: 25pt of capsule padding and a dot that are not drawn, a four-character label where real window labels run seven to nineteen, a seven-cell reading where `9767.2M/0` takes nine, and the wrong gap between chips. Small in three places and generous in one, it offered a 356pt row three slots for a run whose ideal was 344pt of a 304pt column — and the run is `fixedSize`, so the excess went straight past the ground and dragged every other row with it. The estimate is a bound now rather than a better guess: `RowGeometry` owns the arithmetic, `chipLimit` says how many chips the line is offered and `chipCap` how wide each may draw, both dividing one residue, and `SecondaryChipRun` reads its cap from it and splits it between its two runs with the reading served first. No provider's label length and no reading's digit count can push the run past the column.
- A row changed height when its first reading landed. `RowGeometry.lines` asked the fetch result two questions — whether the caption had content, and whether the account was still authenticated — so under Minimal every row was 15pt shorter the moment a reading arrived and the panel shrank around it, and a session expiring with the panel open collapsed the row by its whole detail block and made "Session expired — sign in again" unreachable. One settings-only predicate now feeds the four places that were disagreeing.
- 147% drew as exactly 100%: same figure, same full bar, same square cap. The figure reads a new unclamped percentage; the meter and the dial keep the clamp, because a bar cannot draw past its own track.
- A window with no ceiling rendered as `644.6M/0` in a secondary chip — not a window with no cap but a fraction over zero, on every Claude Code row in the panel. It prints the bare value now, which is the distinction the rest of the row already draws.
- A panel of fifteen failing rows was headed "15 connected". The header's short summary had no failure branch; both summaries read one count now.
- A long account name made the whole identity run vanish — account *and* plan. The third rung of the fitting ladder was the un-elided account, so it was wider than the second and could never be chosen, and `ViewThatFits` fell through to the empty fallback.
- `$10,000.00 5h session` ran the two together without the middle dot every other pair on that line carries. Reserved as well as drawn, so the chip budget moves with it.
- Row actions were one button wide on the three services with no dashboard, putting their refresh 18pt right of every other row's.
- The history chart's threshold label was clipped in half at the shipped 95% on a 560pt pane: the guard compared the label's centre against the plot ceiling instead of its top.
- Fifteen Keychain access dialogs from one refresh. `loadPersisted` checked its cache under one lock, did the `SecItemCopyMatching` outside every lock, and stored the answer under another, so all fifteen provider fetches saw an empty cache and all fifteen asked — and dismissing the first marked the store denied for the other fourteen. That read was also happening on the main actor, during the launch sweep this app documents as silent.
- Budget alerts were evaluated per account against a state keyed per service, so two accounts of one service overwrote each other's remembered fraction on every sweep. A $25 bill split $10/$15 against a $20 budget left both halves under the line the sum had walked past and nobody was told.
- A cancelled sweep wrote a failure over every reading still in flight and armed a backoff against a provider that had never answered badly.
- A per-row refresh moved the reading without moving its stamp, so the freshness line kept reporting the age of the reading the row no longer had.
- The panel's chart button quietly did nothing for the rest of the session, with Settings sitting open on the wrong pane. The window controller's record of the pane on screen was written only where the content view was built, so one click on a sidebar row put the record a pane behind reality and the guard then compared a request against a pane the user had left.
- Choosing a refresh interval cost a full cookie sweep and two overlapping refreshes. The picker called `stop()` then `start()`, and `start()` is not a timer: it re-registers the wake observer, copies every installed browser's cookie database, kicks off a second census behind that, and then fetches every service. The loop re-reads the interval every iteration, so the new one is in force from the next tick.
- "aibars reads the sessions already open in your browsers" appeared and vanished above the list as the launch sweep landed — two wrapped lines and 6pt of padding, a 34pt jump of a window `MenuBarExtra` sizes to its content. It is latched per opening now, wording included, because the locked-session count arrives after the panel is up and swapped the slot to a longer sentence with the boolean standing still.
- The panel's list cap came off `NSScreen.main`, so on a laptop beside a taller external display the cap exceeded the screen the panel opens on: the scroll view never scrolled and drew rows past the screen edge where nothing could reach them.
- Six icon buttons announced their SF Symbol to VoiceOver — "arrow.clockwise", "gearshape", "power" — because `.help` is the accessibility hint rather than the name. A section disclosure spoke its open/folded state nowhere, so both states were the same announcement.
- The menu bar strip style was persisted, written by three presets and compared by the preset matcher while being read by nothing that draws: applying Minimal wrote "Figures only" into the store and the strip carried on drawing marks and figures. Picking a style also left the bar showing the previous bitmap, because the memo key did not include the style or the brand-mark switch — the Appearance preview updated and the menu bar did not, so the setting looked broken while the preview said it worked.
- VoiceOver announced services the strip was not drawing: the label built its own sentence from the unfitted list while the renderer had already built the right one from the fitted list. The label is read back off the image now.
- The strip height tuner minted half-point strips the renderer cannot rasterise crisply, and the fallback sized its canvas to the height it was handed rather than to the mark's own box.
- After one failed open, the Shortcuts pane said "couldn't find its own menu bar item" for the rest of the session, even though the status item returns as soon as the strip is next redrawn.
- `install.sh` named three of the six things an uninstall leaves behind and said that was all of them, which is how up to 400 days of rollups survived it. Its `EXIT` trap did not cover `INT`, so ctrl-c during the build left derived data and a staged bundle behind; and when the move into place failed it deleted the bundle it had just built, having already removed the working copy, leaving the machine with no aibars at all.
- Two cookie tests looped the available extractors and skipped everything that was not Chromium, so on a runner with no Chromium database they passed having asserted nothing — a covered gap reported as a tested one. They skip explicitly now, and CI says so.
- The test suite wrote into one persistent defaults domain shared by every test in the process and every run on the machine, which is the mechanism behind an incident the layout tests already document: a width test measuring a 420pt panel after an interrupted snapshot render. Twelve fixtures also spelled uniqueness with a fresh UUID per run and cleaned up with `removePersistentDomain`, which empties a domain without deleting its file — 37,455 stray plists and 153 MB in `~/Library/Preferences`, growing by about two thousand per full run. Runs now create none.
- Snapshot renders were taken at whatever appearance settings the person rendering happened to have. They run against a scratch domain at shipped defaults now, and the fixture gained a 97% row and light variants at both ends of the width slider — no shipped screenshot had ever contained the near-cap state, so the square cap, the alert weight and the red stop went unlooked-at for two releases.
- Fifteen stale cross-references in doc comments, found by resolving every backticked symbol in every comment in the tree against its declarations.
- Provider rows stayed on "Sign in required" after a successful sign-in — the type-erased wrapper never refreshed its auth flag.
- Settings had no way to set the generic provider's usage endpoint, so it could never authenticate.

## [0.1.0] - 2026-08-01

### Added
- Initial scaffold
- `aibarsCore` framework: models, auth, cookie extraction, providers, views
- `aibars` app target: SwiftUI menu bar app (macOS 13+)
- Five bundled providers: Claude, ChatGPT, Cursor, GitHub Copilot, MiniMax
- Cookie extraction for Safari, Firefox, Chrome, Edge, Brave, Arc
- Manual session token paste as a fallback
- Keychain-backed token storage
- Per-provider enable/disable, configurable refresh interval
- Three menu bar display modes (icon, percent, name)
- XCTest suite for parsers and formatters
- XcodeGen `project.yml`
- `Makefile` (`make build`, `make test`, `make run`, `make clean`)
